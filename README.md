# Subs2Anki · 视频一键句子卡

看 YouTube / B 站的日语、韩语、英语视频时，点一下浏览器插件，把字幕切成**一句一张卡**，并为每句切出**原声片段**，打包成 `.apkg` 双击导入 Anki。翻卡前只听声音，翻开才看到原句 + 译文 + 能跳回视频对应秒数的链接。

> **平台支持现状（请先读这段）**
>
> | 平台 | 字幕自动抓取 | 音频切分 | 说明 |
> |---|---|---|---|
> | YouTube | ✅ 可用（页面字幕轨 / yt-dlp 兜底 / 「显示文字记录」） | ✅ | 主要使用场景，日 / 韩 / 英均可 |
> | B 站 | ❌ **不稳定，默认关闭** | ✅ **可用且精准** | 见下节 |
>
> B 站字幕先后试过 cid 重解析、废弃 `aid` 兜底、WBI 签名接口、页面内登录态、语言与稳定性校验等多轮适配，**仍无法稳定拿到与视频对应的字幕**，所以自动抓取默认关闭。这不是「没做」，是做了但效果不合格，因此不把它当可用功能宣传。

---

## B 站使用说明

- ✅ **能做的**：选好分 P → 自动下载音轨 → 按字幕时间轴切成逐句 mp3 → 打包 `.apkg` / `.tsv` → 导入到按视频命名的子牌组。音频切分是正常且精准的。
- ❌ **不建议依赖的**：自动抓取 B 站字幕轨。无签名接口会串到别的视频的内容，签名接口需要登录态，而很多搬运视频的字幕本来就是压进画面的硬字幕（平台没有字幕轨道）。高级设置里保留了实验开关，仅供想自己试的人。
- ✅ **推荐做法**：**如果你自己有 srt / vtt 字幕文件**（例如「中英+文稿」类视频简介或置顶评论里的文稿、字幕组文件、从 YouTube 原片导出的字幕），拖进插件的「手动导入本地字幕」，其余流程全自动。硬字幕想自动提取需要 OCR，本项目暂不支持。

## 为什么是「插件 + 一个本地小服务」，而不是纯插件

| 事情 | 浏览器插件 | 本地服务 |
|---|---|---|
| 拿当前视频 URL、标题、YouTube 字幕轨 | ✅ 拿手 | — |
| 下载整段音轨、按时间轴切成 100 个 mp3 | ❌ 视频流是 MSE 分片 + 签名，扩展切不了 | ✅ |
| 生成 `.apkg`（sqlite + zip + 媒体映射） | ❌ | ✅ |
| 一键体验 | ✅ 点一下 | 后台常驻，无感 |

所以插件只负责「看懂当前页面 + 抓字幕」，重活交给 `127.0.0.1:8766` 的本机服务。**全程在本机，视频和字幕不上传任何服务器。**端口特意选 8766 —— AnkiConnect 占的是 8765，不能撞。

本地服务没开时插件**仍然可用**：自动降级成导出 `.tsv`，卡片背面放时间戳链接，点一下跳回视频那一秒听原声。

## 三步跑起来

| # | 操作 | 耗时 |
|---|---|---|
| 1 | 双击 `setup.bat`：自动找到 Python 3.10+、装 genanki + yt-dlp、生成图标，并把选中的解释器记到 `runtime-python.txt` | 1–3 分钟 |
| 2 | 安装 ffmpeg：`winget install Gyan.FFmpeg`，装完重开终端；其它系统用各自的包管理器 | 2 分钟 |
| 3 | 打开 `chrome://extensions` → 开「开发者模式」→「加载已解压的扩展程序」→ 选本项目的 `extension` 文件夹 | 30 秒 |
| 4 | 双击 `start.bat`，黑窗口保持开着 | 5 秒 |
| 5 | 打开视频 → 点插件图标 → 选字幕轨 → **✨ 一键制卡** | 几秒～1 分钟 |

产物在 `out/日期_视频名/` 里，**双击 `.apkg` 导入 Anki 就完事**，音频已经打包在里面。

**牌组自动分层**：每个视频会导入到 `Subs2Anki::<apkg 文件名>` 子牌组。例如 `The_World_s_First_Fitness_Resort_40M.apkg` 双击后自动进 `Subs2Anki → The_World_s_First_Fitness_Resort_40M`，不会全堆在一个牌组里。弹窗里的「Anki 牌组根目录」可改前缀（默认 `Subs2Anki`），`config.json` 的 `deck` 是同样的默认值；`.tsv` 导入和 AnkiConnect 直推也用同一个牌组名。牌组 ID 按名字派生，不同视频互不合并。

多分 P 视频（例如 B 站「中英 / 英文」两个 P）先在弹窗的「分 P」下拉里选好，字幕和音频会一起切到所选分 P。**B 站请直接「手动导入本地字幕」**；YouTube 字幕拉不到时可点「用本地服务重新抓字幕」重试。展开底部「诊断信息」可查看每一步的 HTTP 状态。

## 卡片长什么样

**默认「先听」模式**（适合听写 / 影子跟读）

| | 内容 |
|---|---|
| 正面 | 🎧 原声播放按钮 ＋ **0.5× / 0.75× / 1× / 1.5× / 2× 倍速按钮**，只有声音，**没有文字** |
| 背面 | 原句（大字）＋ 对照译文 ＋ `▶ 视频标题 · 03:12`（点击跳回原视频那一秒） |

插件里可切成「看句子 + 听」模式：正面同时显示文字和音频。
有双语字幕轨（或 YouTube 自动翻译轨）时，译文会自动按时间轴对齐到句子上。

### 倍速怎么用

| 操作 | 效果 |
|---|---|
| 点 `0.5×` / `0.75×` / `1×` / `1.5×` / `2×` | 立刻按该速度**从头重播**这一句，按钮高亮 |
| 翻到下一张卡 | 记住上次选的速度并高亮（存在 webview 的 localStorage） |
| 点原生小喇叭 / 按 `R` | Anki 自带播放，固定 1×；也是 JS 被禁用时的兜底 |

原理：Anki 的 `[sound:]` 不支持调速，所以正面额外放了一个 `<audio>` 元素，用 `playbackRate` 控制；`[sound:]` 仍保留，保证媒体文件被 Anki 正确登记与同步。控件自包含在 **Audio 字段**，脚本在**字段和卡片模板里各放一份**（双保险：部分客户端会过滤字段内 JS），因此 `.apkg` 和 `.tsv` 两条导出路径都有倍速。

- 改档位：编辑 `server/exporter.py` 的 `PLAYBACK_RATES`（当前 `[0.5, 0.75, 1.0, 1.5, 2.0]`），重新制卡。
- 已导入过的旧卡：重新生成并导入即可；走 AnkiConnect 时会自动同步模板与样式。
- AnkiWeb / 禁用 JS 的客户端：倍速按钮不可用，原生小喇叭仍可 1× 播放。

## 断句参数（插件「高级设置」里可调）

| 参数 | 默认 | 作用 |
|---|---|---|
| 最短句长 | 1.0 s | 太短不切，避免把 `Yes.` 单独做成一张卡 |
| 最长句长 | 12 s | 遇到没标点的长句强制断，防止一张卡几十秒 |
| 停顿切分 | 0.65 s | 字幕碎片间出现明显换气/空白就断句 |
| 单句字数上限 | 90 字 | 与最长句长并列兜底 |
| 音频前后留白 | 0.12 / 0.28 s | 切出来的句子不吞头、不吞尾 |

断句按「句末标点 + 停顿 + 长度上限」三重判断；日/韩拼接时不插空格，英文按词插空格。日语无标点字幕会额外识别 `です / ます / ました…` 等敬体词尾。

高级设置里还有：**本地音频文件**（跳过 yt-dlp 直接切片）、**读取浏览器 Cookie**（YouTube 反爬与 429）、**代理**（YouTube 下载用，留空自动读系统代理）、**实验性 B 站字幕抓取**（默认关，适配未成功，不建议依赖）、**手动导入本地字幕**（srt / vtt / json，B 站推荐走这里）。`config.json` 里也有对应的 `proxy` / `cookies_from_browser` / `deck` 默认值。

## 常见情况对照表

| 现象 | 原因 | 怎么办 |
|---|---|---|
| B 站「没返回字幕」 | 自动字幕抓取默认关闭（实验性，多轮适配后仍不稳定） | 用自己的 srt/vtt「手动导入本地字幕」；音频切分不受影响 |
| YouTube 字幕轨是空的 | 需要先加载过播放器字幕 | 打开一次 CC 字幕 /「显示文字记录」，刷新页面再点插件 |
| 卡片没有声音 | ffmpeg 没装，或 yt-dlp 下载失败 | 看服务状态页；也可用其它下载器下好音频，在插件「高级设置 → 本地音频文件」填绝对路径 |
| 完全没字幕的视频 | 当前版本依赖平台字幕轨，不含语音识别 | 见下节 |
| Anki 导入后没声音 | 用了 `.tsv` 而不是 `.apkg` | 优先用 `.apkg`；`.tsv` 需把音频文件复制进 Anki 的 `collection.media` |
| ffmpeg 装了但服务仍显示缺失 | 终端没重开、PATH 没刷新 | 重开终端；或把 `config.json` 里的 `ffmpeg` 改成绝对路径，如 `C:/ffmpeg/bin/ffmpeg.exe` |
| 插件一直显示「服务未启动」但服务明明在跑 | 代理 / 安全软件拦了本机回环，或端口改过 | 浏览器直接开 `http://127.0.0.1:8766` 验证；改端口要同步改 `background.js` 的 `BASE` 和 `manifest.json` 的 `host_permissions` |
| 端口被占（AnkiConnect 用 8765） | 本项目用 8766 | 改 `config.json` 的 `port`，同步改上面两处 |
| 双击 `.bat` 一闪而过 / 没反应 | 旧脚本是 UTF-8 + LF 换行 + `chcp 65001`，cmd 按 GBK 解析中文时会把命令拆坏 | 已修复：全部 `.bat` 改为 **GBK + CRLF** 且去掉 `chcp`。用编辑器改过 bat 后，先跑 `python tools/normalize_bat.py` 再双击 |
| 装依赖时报错 / 装到了旧版 Python | 某些机器 PATH 里的 `python` 可能指向 Python 2.7 或其它软件自带的解释器 | 脚本优先用 `py -3` 并逐个校验 `>=3.10`，结果缓存在 `runtime-python.txt`（该文件不入库）；`setup` / `start` / `demo` 共用同一个解释器 |
| B 站自动字幕是空的 / 内容与视频无关 | 多轮适配（cid 重解析 → 废弃 `aid` 兜底 → `/x/player/wbi/v2` WBI 签名 → 页面内登录态 → 语言与稳定性校验）**仍未稳定解决**：无签名接口会串轨，签名接口需登录态，且很多搬运视频是压进画面的硬字幕 | 这是已知限制，不是配置错误。自动抓取已默认关闭，请用自己的 srt/vtt「手动导入」；音频切分照常可用 |
| 想再试一次 B 站自动字幕 | — | 高级设置勾选「实验性：尝试自动抓取 B 站字幕」，展开诊断看 `code` / `need_login` / 字幕轨条数；结果仍可能不对，请务必核对预览 |
| 多分 P 视频字幕和音频对不上 | 不带 `p` 参数时 yt-dlp 会当成合集，默认只下 p1 | 弹窗新增「分 P」下拉，字幕与音频一起切到所选 P，制卡 URL 自动带 `?p=N` |
| YouTube 音频下载失败 | yt-dlp 用了错误的代理（例如宿主注入的本地代理返回 502） | 服务端只对 YouTube 显式使用系统代理，且先探测端口是否监听；也可在高级设置手填代理 |
| YouTube 字幕轨 `HTTP 200 / 0B` | 扩展后台是跨域请求（Origin 为 `chrome-extension://`），YouTube timedtext 对它会返回空 | 改为**在页面里同源请求**，并依次试 原始 baseUrl / `fmt=json3` / `vtt` / `srv3`；仍空就自动让服务端 yt-dlp 兜底。终极兜底：在视频下方点「显示文字记录」，插件直接读页面段落，完全绕开 API |
| YouTube 字幕拉取失败、刷新没用 | `ytInitialPlayerResponse` 可能是 SPA 切换前的旧视频；裸 `timedtext` 请求现在返回空（需带签名） | 已按 URL 的 `v` 校验并丢弃旧响应；服务端兜底加了 `--sleep-requests 1`，实测能拿到 518 KB 字幕。若仍报 429，在高级设置勾选读取浏览器 Cookie |
| B 站只抓到「中文 · AI」字幕，想要日语 | B 站 AI 字幕是中文语音识别；日文字幕若是压在画面里的硬字幕，平台没有对应轨道 | 用 YouTube 原片制卡，或把自己的日文字幕 srt/vtt 手动导入 |
| 点「用本地服务重新抓字幕」对 B 站没用 | 该按钮只对 YouTube 生效；B 站字幕走签名接口，yt-dlp 在 Chrome 运行时读不到 cookie 库 | B 站请改用「手动导入本地字幕」 |
| 不知道卡在哪一步 | — | 弹窗底部「诊断信息」记录了 bvid / cid / 分 P / 每个 API 的 HTTP 状态 / 字幕解析条数 / 制卡 URL，复制出来即可定位 |
| 日语 / 韩语视频抓不到字幕 | ① 该视频在 YouTube 上根本没有字幕轨；② 旧版按 UI 选的 `en` 过滤 `--sub-langs`，把 ja/ko 原字幕挡掉了 | 现在明确区分「没有任何字幕轨」与「429 限流」；字幕抓取固定覆盖 ja/ko/en/中文，先只抓你选的语言（避免限流）再放宽；「语言」下拉只影响断句和文件优先级，不再过滤字幕语种 |
| B 站字幕是不是就提取不到 | 平台上确有 CC / AI 字幕轨，但本项目多轮适配后**仍不能稳定可靠地取到**，因此不作为可用功能提供 | 按文首「B 站使用说明」：音频正常切，字幕用自己的 srt/vtt 手动导入 |
| YouTube 字幕 429 限流 | 当前网络 / IP 被字幕 CDN 限流 | 稍等几分钟重试、勾选读取浏览器 Cookie；最快是在视频下方点「显示文字记录」后重新打开插件，插件直接读页面段落，完全不走字幕接口 |
| 倍速按钮点了没反应 | AnkiWeb / 部分客户端禁用字段内 JS | 用下面的原生小喇叭（1×）；桌面 Anki、AnkiDroid 正常，模板里已备份一份脚本 |
| ffmpeg 装了却报 WinError 193 | winget 的 `WinGet\Links\ffmpeg.exe` 是应用执行别名，不是真 exe | 服务已自动定位到 `WinGet\Packages\...\bin\ffmpeg.exe`；自定义安装可在 `config.json` 的 `ffmpeg` 填绝对路径 |
| 重复导入 | 卡片 GUID 由 `URL + 序号 + 句子` 生成，Anki 会自动去重 | 无需处理 |

### 关于「没有字幕的视频」——当前边界，说清楚

这一版**不做语音识别**，它吃的是平台字幕轨（YouTube 的 CC / 自动 ASR 字幕）或你自己的本地字幕文件；B 站请按文首说明手动导入 srt/vtt。真的没有字幕时：

1. 用 `--subtitle` 导入本地 `.srt / .vtt`；
2. 或者后续接 `faster-whisper` 本地转写 —— 入口已经留好了：`server/models.py` 的 `parse_subtitle` / `normalize_cues` 只认统一的 `Cue(start, end, text)`，任何 ASR 结果只要转成这个格式就能直接进流水线。你要的话我可以接着把这一层补上。

## 不用浏览器也能用（命令行）

```bat
python -m server --demo
python -m server --url "https://www.youtube.com/watch?v=xxxx" --subtitle ep01.srt --lang ja
python -m server --url "https://..." --subtitle ep01.srt --audio-source ep01.m4a --title "第1集"
python -m server --url "https://..." --subtitle ep01.srt --translation ep01.zh.srt --ankiconnect
```

`--audio-source` 可以跳过 yt-dlp，直接切你本地已有的 mp3/mp4/m4a。

`--demo` 里的音频是**合成提示音（占位）**，只用来验证「音频 → Anki 媒体 → 卡片」链路是通的，不是真实语音。
